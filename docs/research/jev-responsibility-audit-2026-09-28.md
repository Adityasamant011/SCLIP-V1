# Jev responsibility audit — 2026-09-28

This is an ownership and evidence audit of the current working trees, not a production change or a cost-saving claim. External model descriptions were checked against [OpenRouter's Jev page](https://openrouter.ai/typesafe/jev-1.13), [its Jev tutorial](https://openrouter.ai/blog/tutorials/how-to-use-jev/), [its Jev/LLM comparison](https://openrouter.ai/blog/tutorials/jev-vs-llm-when-to-use-each/), and the community [fast-jev-compaction implementation](https://github.com/tamaratran/fast-jev-compaction). The comparison benchmark and community plugin demonstrate possible patterns, not Sclip savings.

## Current architecture and availability

- Hermes is the general creative agent. Its `tool_search`/`tool_describe`/`tool_call` bridge defers the large WeftCut catalog; the patched deferred-call guard only rejects a malformed selected tool call with missing nested required fields. It neither chooses a tool nor edits.
- The Electron main process hosts WeftCut MCP against ProjectActor's canonical project. Cached transcription and `get_media_context` supply original, timestamped evidence; `detail="segments"` is compact, while detailed range/word reads remain available. `apply_rough_cut_plan` atomically executes **Hermes-selected** ranges/order, with ProjectActor history and linked A/V. `apply_transcripts` returns created caption IDs. Imported media, basic overlays/B-roll, transform/effect/audio tools, local Qwen `vision_inspect`, composed preview, and user-only production export exist. Not every editorial/visual failure is solved by these primitives; Qwen can still misjudge a partially cropped head.
- `sourcePassageEvaluation.ts` and `jevClient.ts` implement one read-only Jev role: 1–4 imported cached-transcript sources, up to 120 local passage candidates, up to six bounded Decisions API batches, three Noul questions per candidate (relevance, self-containedness, surrounding-context need), top-K=12 default, exact references/neighbors/coverage/uncertainty, no silent probability cutoff, no fallback or mutation. The model is pinned to `typesafe/jev-1.13` via the existing secure OpenRouter credential. This is **working when enabled**, not proof of benefit in ordinary use.
- Ordinary Sclip only adds `evaluate_source_passages` to `tools/list` when `SCLIP_JEV_ENABLED === '1'` (`src/main/index.ts`). Default is disabled; it is not a normal settings toggle, and this task's environment/launch configuration has the flag unset. A separately launched process could set it explicitly. In opt-in disposable sessions it was advertised and Jev actually ran, but Hermes also ignored it in other sessions. No automatic Jev call occurs. The user's main model remains independent.
- Hermes has native deterministic `prune_tool_results_only`, but the current Sclip profile does not configure proactive pruning. Hermes's current checkout contains a `SclipStyleMemoryProvider` and event/profile consolidation code; the active Sclip Hermes memory directory has no `style-events.jsonl` or `creator-style-profile.json`. Thus style retrieval/admission exists as latent/partial Hermes code, **not** an observed Sclip creator-style-learning product or Jev integration. Do not activate or redesign it on this evidence.

## What the model can do

Jev consumes **text** state plus bounded questions and returns typed `choice`, `noul`, or `score` answers. Parallel questions can share state. It does not generate a narrative, inspect pixels or audio, perform reliable arithmetic/counting, or run an agent loop. Its answer distribution is not a calibrated probability that an editorial decision is correct. The local implementation currently uses only Noul; the model's wider Choice/Score capability does not imply Sclip needs those interfaces. Programmatic thresholds should be calibrated on Sclip examples before they can suppress evidence. [OpenRouter tutorial](https://openrouter.ai/blog/tutorials/how-to-use-jev/), [comparison](https://openrouter.ai/blog/tutorials/jev-vs-llm-when-to-use-each/).

## Editing-process ownership

| Activity, from import through finish | Primary owner | Jev fit and risk |
| --- | --- | --- |
| Import, identify files, cache/probe media, timestamp and frame/sample arithmetic | Deterministic code; transcription for speech, Qwen/local media analysis for pixels | No Jev for mechanical facts or raw modalities. |
| Understand long spoken source and retrieve candidate passages | Hermes chooses question and whether to use original reads; optional Jev ranks text candidates | Best current fit, but false negatives can hide story setup. |
| Choose hook, story, cut boundaries, pacing and structure | Hermes | Jev can supply passage evidence, never final selection. |
| Place already-decided clips and manage links/history | Existing ProjectActor operations, optionally bulk executor | No Jev; batching removes mechanical primary-model turns. |
| Caption wording/style/layout, text/graphics, B-roll selection | Hermes with source, asset and visual evidence; deterministic editor executes | Optional future text-only relevance/QA hints, never automatic creative placement. |
| Reframe/inspect composed frames, audio mix and cut quality | Hermes evaluates local Qwen/composed render and technical audio facts | Jev cannot see/hear raw content; text-only QA is weak evidence. |
| Review, revise, stop and export | Hermes decides completion; user initiates production export | No Jev stop/review authority. |

**Reject as Jev ownership:** tool routing (Hermes's deterministic BM25 progressive disclosure already works, and routing would constrain agency), clip placement/frame arithmetic (exact ProjectActor code), creative hook/story/pacing/effects selection (open-ended editorial work), raw visual/audio inspection (Jev text-only; Qwen/transcription serve those modalities), final edit review/stop/export (requires whole-output judgment and user-only export). Jev may label text offered by one of those tasks, but must not drive them.

## Economic comparisons from actual evidence

| Source path | Expected main-model work | Extra Jev/tool volume | Principal risk |
| --- | --- | --- | --- |
| **A. Compact original transcript** | One or more normal range reads. Historical free sessions read 6–9 chronological windows and sometimes nearly all 575.7 s. | No Jev charge; compact segments omit word arrays. | More input/tool turns when the desired topic is unknown, but full original evidence is available. |
| **B. Jev shortlist + expansion** | Hermes must first choose Jev, then inspect K excerpts and often request original neighbors. In the one shadow run K12 returned 14,826 bytes of JSON vs 21,533 bytes compact full-source JSON (31.1% smaller), but omitted much airport setup; the central mentor passage was rank 4. | Three paid Jev batches in that shadow test, under $0.001 total; actual Hermes runs also made failed guessed calls or selected Jev late. | Shortlist can be extra work/cost if Hermes still reads most source, or an editorial regression if it does not expand. No matched GLM saving proven. |
| **C. Known timestamp → direct range** | One scoped original read, potentially no discovery turn. | Jev would only add a request/result. | Minimal retrieval risk; Jev generally unnecessary. |

The historical 52-call unfinished GLM edit spent about $0.924, but much waste came from mechanical placements and broad state reads, not something Jev should own. The K12 Jev response is smaller than the full compact transcript payload, yet its missing setup can force refetch. Cost must be measured per acceptable completed edit, not per helper call. ## Roadmap / next Jev validation

- **NOW:** Keep current source-passage retrieval and context-sufficiency judgments opt-in. Next evaluate **one matched source-understanding comparison**—compact original reads versus optional Jev K12 with original expansion—using the same main model, source and brief. Score winner/story recovery, setup/payoff coverage, main turns/tokens, Jev cost, total cost and latency. Do not enable Jev by default merely because its provider call is cheap.
- **NEXT:** Consider text-described asset relevance only after current media-library use demonstrates costly candidate browsing; do not build it proactively.
- **LATER:** Creator-style retrieval/admission and source taxonomy, only after real durable preference/asset data and product consent exist.
- **EXPERIMENTAL:** Redundancy hints, semantic QA and Jev context relevance. Compare the existing deterministic pruning first; never silently delete original evidence.
- **REJECT:** Jev routing, mechanical editing, creative control, raw vision/audio, final review/stopping/export.

Invariant: **Jev narrows; Hermes chooses; deterministic code executes; Hermes reviews.**
