# 0087: Current constraints, resumable review and preview ownership

Status: implemented; live creator media/performance acceptance pending

Hermes remains Sclip's sole foreground editorial agent. It chooses story, cuts, visual concepts, parameters, asset providers within existing permissions, repairs and no-repair conclusions. The host supplies current facts, technical invariants, resource ownership and truthful delivery status. It does not prescribe a creative template, require an animation recipe, force every optional tool into every video, or substitute learned habits for current instructions.

Explicit duration constraints distinguish exact, maximum, minimum and range. Latest accepted corrections supersede older targets while retaining the supported prior brief modalities and contextual brief. Maximum means a ceiling, not a padding target. Ambiguous constraints are not invented. The parser deliberately supports literal English clauses rather than claiming arbitrary semantic understanding.

Empty-track setup and pool-only imports do not constitute a rendered repair. Their unchanged output can rebase factual receipts; genuine authored changes invalidate evidence. Atomic multi-operation repair remains one commit/undo. Speech placement and batch insertions can explicitly anchor to a current layer/preceding transaction reference's exact end in the same composition. The agent still chooses whether clips should be consecutive.

Accepted turns receive a fresh bounded media inventory, including imported images, through the authenticated existing context channel. Cached evidence acquisition has a five-second deadline and an explicit unavailable/recovery result; it never triggers a whole-project perception pass.

prepare_review/review_job reuse the actual sensing/render handlers and scoped authority, validation and evidence guards. A handle/running job is not proof. Await returns actual results; a later turn/opening cannot consume old jobs. Cancellation retains physical resource ownership until settlement. This is resumability across individual transport waits, not recovery of processes after app exit. Independent preparation remains optional and can overlap. Concurrent Kokoro auditions use a bounded eight-request, eight-millisecond microbatch with one model initialization; isolated sequential calls still start a process. Text, speed, voice and cache identities are preserved.

One physical Motif capture host now prioritizes explicit inspection, interactive requests and background warming. It discards only queued obsolete requests for the same interactive owner; it never races physical seeks. Live timeline inspections serialize playhead ownership, respect frame-grid positions, and avoid restoring over a creator's changed playhead. Raster cache LRU has a 256 MiB estimated RGBA payload budget plus currently displayed retained frames (and at least one oversized frame); warm capacity adjusts to actual frame size. GPU/Chromium/encoded resource memory is additional. Resolution, fps and exported pixels are unchanged. Persistent baking remains opt-in; this does not establish real-time 1080p60 HTML rasterization.

Native text results have a single versioned success/error envelope that preserves receipts/data and avoids duplicate legacy wrapping. Standard MCP content and image blocks remain compatible. Common timing/ID contracts and examples describe actual caller choices; failures categorize the primary error rather than review boilerplate. Unknown source IDs are rejected before budgets. At most three technical acquisition recoveries are allowed; no unlimited rescan allowance is introduced. get_completion_status and the terminal's VERIFIED/INCOMPLETE label reflect authoritative lifecycle state even on iteration exhaustion.

Validation uses synthetic state, transport, capture, cancellation, batching and native formatter contracts. No provider calls, private-video runs or live playback performance conclusions form part of this engineering acceptance. The creator performs those acceptance checks separately.
