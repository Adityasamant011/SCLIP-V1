# Minimal generated-speech portability proposal — not implemented

The prior installed-app test establishes a specific failure: same-profile reopening and complete-folder transfers with the project conform work, but a receiver cannot rebuild/export speech if both that conform and the originating profile-cache MP3 are unavailable. The source asset has path_rel=null and is not in project Media. No persistence change belongs in the review-guidance experiment.

Proposed patch boundary: the workspace-backed, non-preview synthesize_speech success path in state/hybrids.ts. Reuse the existing import-copy queue, content hash/destination naming, media:workspace_paths write-back, set_media_workspace_paths actor command and normal save machinery. Do not add another media store or rewrite rendering. Keep preview_only results transient; unsaved/no-workspace projects must not be falsely reported self-contained.

After a successful authorized one-transaction place_synthesized_speech, enqueue copying its generated original into the owning workspace Media directory, as normal imports already do. Reuse native copy_to_workspace integrity/cancellation behavior. On verified completion, use the existing actor write-back to record path_abs plus project-relative path_rel and stable content hash. Keep the cache source until the durable copy is verified; do not delete creator cache or memory. A deduplicated/reused media item also needs its existing persistence status checked; imported=false alone must not skip a missing durable copy.

Queueing is not completion. Report persistence pending/ready/failed separately from successful timeline placement, and never report a queued item as portable. On copy failure preserve the actual placed audio, expose an actionable status/retry and retain the source; do not repeat placement, claim the edit failed atomically, or silently remove speech. Preserve undo/redo and single-authoritative-writer behavior.

Before implementation, verify the exact existing queue completion ownership seam. Native enqueue_workspace_copy captures a workspace root, but the emitted media:workspace_paths event currently shows media ID/path/hash without an explicit opening token. Do not assume that is sufficient for a delayed job involving a reopened/copied project. Bind/check owning project opening, asset/source identity and copy generation at final write-back; stale completion must not mutate another opening or resurrect an undone/removed asset. Preserve the existing pre-placement cancellation authority checks, and cancel only owned work. Any small ownership adaptation must be regression-tested, not used as a reason to redesign all persistence.

Acceptance: local Kokoro synthesis in a fresh disposable workspace; verified MP3 under Media with path_rel; wait for durable completion; save/close; copy the project with derived Cache omitted; make ALL original source/conform paths unavailable by retaining their directories elsewhere; open in a second fresh profile; regenerate conform; playback/export/decode and compare speech against original. Include same-profile and full-folder controls, preview-only behavior, unsaved workspace handling, copy failure/out-of-space fault injection, repeated/deduplicated synthesis, cancellation before/during copy, project switch/reopen, undo/remove and a subsequent valid synthesis. Real projects, installed app and original test evidence stay untouched. No implementation or safety acceptance is claimed by this proposal.
