## Exact shortest roadmap

### Milestone1 — Remaining critical code defects

**Build/fix:** R1 cancelled late synthesis writes; R2 independent media requirements; R3 inspection-start freshness; R4 owned render interruption/release. Add captured request/opening/epoch identities and a single owned cancellation propagation mechanism to the existing operations, not a second timeline owner. Fix R5/R6 bootstrap/model packaging in parallel only if it does not obscure the cancellation regression work.

**Why:** a user must be able to stop an operation, and “completed” must correspond to the requested streams and current evidence. These are deterministic code/integration defects independent of model editorial skill.

**Already exists / retain:** ProjectActor sole-write authority, atomic transactions/history, completion serials/acquired-receipt invalidation, native task hooks, actual compositor/decode proof and physical transcript bounds. Keep the existing validated system; extend the missing ownership edges.

**Do not rewrite:** WeftCut Rust engine, ProjectActor, Hermes conversation loop, creator store or renderer. Do not auto-edit clips to satisfy a validator.

**Proof / visible improvement:** unchanged cancel/mixed-media/in-flight repros fail honestly or terminate cleanly; valid positive controls complete; cancelled tasks create no late layer and release the export lock; next request works. Users can trust Cancel and the technical readiness status.

### Milestone2 — Reliable autonomous video editing and review

**Build/fix:** R7 legal review progression, with exact actionable state/action/receipt examples. Retain the proven two-window validation/assembly/export; extend paired A/V and strict-review cases; reduce model argument failures by grounding schemas and applied-state facts. R8 chosen-range boundary context, approximate-duration tolerance, fit guidance and generated-versus-observed review distinctions. R9 labeled action evidence and bounded local perceptual improvements if validated. Preserve actual own review, never credit QA after end.

**Why:** the engine executes correct edits but the agent loops through review state, invents unapplied assemblies and accepts poor range/framing choices. “Upgrade AI” is not a testable deliverable; the concrete workflow contracts and repeated briefs are.

**Already exists / retain:** source understanding/speech-context tools, calculate_video_fit, full current frame/audio inspection, dynamic search/describe/call, reviewer diagnostics, revision-control lifecycle, local Qwen/Whisper and guarded actual artifact validation.

**Do not rewrite:** no fixed transcribe→cut→caption pipeline, no predetermined source ranking/genre skeleton, no forced cover crop, no host-owned subjective repair. Hermes must choose the actual story and response to evidence.

**Proof / visible improvement:** rerun A-H and audio exactly, including twice-repeated tutorial/product/title; preserve failures; full independent render/QA after frozen outcome. Then meet held-out objective/editorial/reviewer gates. Users get a coherent chosen excerpt and a verified end without supervising every review-tool call.

### Milestone3 — Creator style learning and video-quality validation

**Build/test:** R10 real interpretation→supported candidate→persistence/context→actual future editing across caption design, pacing, framing and audio balancing; conflicts/current-request override and irrelevant evidence controls. R11 generation truncation survives source-cache/context. Resolve any proven missing foreground learning step with existing creator_style_memory and scoped evidence, plus concise guidance if actual traces require it. R12 readiness ergonomics improves speech workflows.

**Why:** explicit preference application and one reused font correction are positive, but they do not establish a general style-learning promise. Product QA must distinguish a stored sentence from a change in a new edit that creators prefer.

**Already exists / retain:** authoritative correction provenance, grouped evidence/proposal links, candidate hypotheses with support, creator/project scope, persistence/revisions/controls and foreground context. The actual source64→User28→later28 path works; use it as a starting fixture.

**Do not rewrite:** no neural training pipeline, autonomous background memory inference, KV replacement or generic USER.md mirroring. Do not automatically promote a single experiment into global style.

**Proof / visible improvement:** meaningful multi-project study meets style gate, two reviewers approve outputs and trace shows why the new edit follows supported evidence; creator can reject/override candidates. SCLIP learns useful caption/pacing/mix preferences without repeatedly asking the creator or leaking another creator's style.

### Milestone4 — Packaging and supervised creator testing

**Build/test:** ship pinned bundled Hermes and supported Darwin model/runtime provisioning (R5/R6); R13 clear runtime/error recovery and consistent status counts; complete agreed core R14 recovery/export/UI acceptance. Verify signed app on clean supported machines, no developer path, import/prompt/timeline/user correction/save/reopen/export, lost provider/local model recovery and safe cancellation. Run≥5 consenting supervised creators with isolated/copied projects before beta expansion.

**Why:** a workspace using an existing Python venv/Homebrew/model cache is not an installable AI editor. Real creators reveal ambiguous requests, correction patterns and recovery failures missed by synthetic controls.

**Already exists / retain:** package builder/license/skill gates, bundled FFmpeg, working unsigned GUI/import/edit/export path, Settings and runtime status, native hooks and existing editor after agent session.

**Do not rewrite:** no production installation over the developer user's app during verification, no dependency/model upgrades without need, no enabling every optional Hermes service. Keep existing tool/skill/runtime versions pinned while validating portability.

**Proof / visible improvement:** clean-machine complete workflow and recommended supervised creator gates pass, no false readiness or unrecoverable state, all supported resources/licenses/signatures/recovery paths present. Users can install SCLIP and create an acceptable video without the developer checkout or hidden local setup.

Packaging provisioning can start alongside Milestone1, but public release waits for all must-pass safety, task-quality and supported-platform gates. Do not add optional eight-verb exposure, neural style training or unrelated integrations to the critical path without a reproduced creator blocker.

This reconnaissance is complete as an evidence-backed release decision, not a universal functional certificate. Unproven rows are explicit remaining acceptance work. Deliver these reports and stop; implement only under a subsequent authorized phase.
