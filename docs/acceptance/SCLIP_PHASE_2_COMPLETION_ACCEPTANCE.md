## 2. Verified defects repaired during Phase 2

1. Natural Hermes answers could omit `end_agent_session`; the app only observed PTY bytes/process exit, leaving the trusted outcome unverified without another model turn.
2. Original output acceptance could be satisfied by a duration or state description without proving a complete video artifact existed and decoded.
3. Equal-content A→B→A revisions could revive observations. Host-observed revisions now invalidate acquired evidence; a monotonically increasing epoch also binds review and delivery proof.
4. A large PTY redraw hid the input-ready marker because only the tail of the chunk was scanned. Actual gap run1 exposed this; the whole new chunk plus a small split-marker tail is now scanned. Run1 remains an interrupted failure; run2 succeeded.
5. Cancelling during async delivery validation could leave a late success eligible. Cancellation now changes the request serial immediately, records cancelled/unverified, suppresses feedback and wins over otherwise normal task-end metadata. A future real request can restart without inheriting completion.
6. `text_response(finish_reason=length)` is an output-token exhaustion, not a normal finished task. Only explicit stop/end-turn termination qualifies; exhausted/unknown endings remain unverified.
7. Tutorial run1 closed a review after a video render without the requested current rendered speech. The final end rejected it, while the completed guard blocked further inspection. All relevant requested modalities are now required **before** conclude/complete/finalize, so Hermes can still inspect missing evidence. The failed run is retained, not upgraded.
8. A render explicitly reporting `has_audio:false` no longer supplies an audio modality receipt. A bare `valid:true` is insufficient: delivery needs decoded media, bounded actual duration and required stream facts.

Harness-only mistakes (offline gateway credential/startup, wrong Audio tool name, root working directory, compact transcript assumptions, ffprobe path and post-completion MCP inspection) are retained in logs. They were corrected in scratch orchestration; accepted production assertions were not relaxed to hide them. The synthetic MCP transport fixture uses an explicit decode I/O seam because its source and PNG bytes are fake; actual compositor/decode acceptance is measured separately.

## 3. Cause of missing handshakes

Upstream Hermes `agent/conversation_loop.py` can return a final text answer without choosing another tool. `agent/turn_finalizer.py` emits `on_session_end` with turn/task IDs, completed/failed/interrupted and a termination reason. The interactive CLI then stays alive for another user message. **CLI process exit and provider/tool silence cannot establish this per-task event.** The prior terminal bridge had neither this event nor a reliable completion checkpoint; the previous acceptance harness used quiescence, which this report does not upgrade into completion proof.

Upstream `pre_llm_call` supplies the original request and parent-session identity; subagents are ignored by the observer. The existing `pre_verify` code-edit gate does not cover general video tasks. A failed tool can be corrected by Hermes; temporary 429/retry or a paused provider stream is not completion. Cancellation, crash, interruption, timeout, budget exhaustion, unfinished/background work and unavailable evidence retain explicit unverified outcomes.

## 4. Narrow architecture

The app stages a small Python **hook-only** plugin in the isolated Hermes home, using upstream `hermes_cli.plugins` discovery and `hermes_cli.lifecycle.invoke_hook`. It forwards bounded metadata over authenticated loopback HTTP. MCP bearer authentication plus a separate launch secret bind the route to the actual native terminal, project actor/opening and task. Connection IDs are tracked for existing work ownership; the observer cannot end another client's work. Source content is not sent by this observer.

`CompletionCheckpoint` observes the authoritative actor, waits up to30s for pending authorized MCP operations after a genuine task end, checks native background-work status, literal brief requirements, current critique, current Hermes decision and rendered receipts, source fingerprint and current revision. It also validates a full temporary artifact through the existing renderer export surface, ffprobe and full FFmpeg decode. Reopen/restart, mutations, source changes and newer requests invalidate readiness. Duplicate turn-end events share one finalization and do not duplicate feedback.

At most **two labelled host feedback turns** go into the **same native PTY conversation**, after a structured end plus input readiness, within a10-minute horizon. A readiness marker alone never establishes completion. No observer-launched model, forged end tool call, fake review, inferred repair or background agent is introduced. Final unavailable/exhausted outcomes stay incomplete. Explicit `end_agent_session` uses the same actual output proof requirements. Renderer status distinguishes running, review required, completed, incomplete, cancelled and interrupted.

## 5. Creative ownership

Every actual editorial mutation is still chosen by Hermes and submitted through existing tools/ProjectActor. The host reports actual microsecond units, duration/layers/source windows, missing required media, warning ranges and review stage; it supplies no cut list, source selection, scale/position/color patch, music choice, title or transition. Warnings about visual gaps and A/V offsets explicitly allow intentional choices. Black and title cards count as authored visuals; audio-only requests are accepted without demanding video. The synthetic fixture's no-change explanations belong to the fixture; live Nemotron decisions and mutations are separately recorded.

The observer has no provider client, `register_tool`, editor mutation or review decision. Production native discovery is unchanged. Accepted current no-repair decisions are not forced into changes. Failed live outputs have not been secretly repaired by the audit.

## 6. Objective output acceptance

`finalOutput.ts` validates actual composition duration and authored enabled layers, literal requested video/audio/speech intent, source presence in the pool and source windows within physical metadata plus one-frame rounding. Recursive authored visual coverage excludes disabled/static-transparent layers. It reports uncovered intervals and A/V source/rate differences as observations, not mandatory fixes.

A full temporary production-compositor artifact is probed and actually decoded. Expected streams and timeline duration must match (frame/100ms container padding allowance); successful proof includes an artifact SHA-256. Proof binds exact reviewed state, epoch and current source size/mtime fingerprint. Complete outputs exceeding the bounded120s QA window remain unproven, never certified from a prefix. State/source changes during validation refuse stale success. Required current source files must exist as regular files; a surviving cached proxy cannot certify a missing original. Source freshness uses size/mtime, not an adversarial content-integrity guarantee. The normal full-range cap is120s (existing configuration can raise it to300s). FFprobe/decode have deadlines; the compositor export itself has no independently proven hard hang deadline. Cancellation still invalidates a late result.

Seven actual Electron/MCP/native-plugin-loader cases in `output-validation-final-results.json` all pass: correct30video→completed; correct-duration audio-only30 requested as video→incomplete; empty video→incomplete;30,000seconds→incomplete; intentionally justified25s leading visual gap→completed; legitimate14s audio-only→completed; intentional30s black Color→completed. They use actual exported media and decode, with explicit synthetic review decisions and no hosted inference. These are objective validator/transport proof, not autonomous editing success.

Limits: potential authored coverage is not pixel/subject visibility; duration parsing is deliberately narrow; full decode is not meaning, synchronized dialogue, silence suitability or storytelling. Current speech inspection is required for a speech brief, but ASR/vision and Hermes interpretation remain fallible. An actual render receipt proves the generated artifact, not that a model watched every frame. Readiness labels explicitly limit their scope to recognized measurable requirements, current review and media proof.
